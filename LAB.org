* Benchmark matrix

The current experiment matrix is defined in [[file:config/experiment.toml][config/experiment.toml]].
The current model registry is [[file:config/models.toml][config/models.toml]].

The main causal comparison now has three explicit conditions:

- =base=: one model completion with no agent loop or Prolog;
- =agent_plain=: the same model with an iterative agent/revision loop but no Prolog;
- =rlm_verified=: the same turn budget with Prolog-RLM symbolic queries and verification.

Legacy names such as =vanilla= and =self_recursive= remain accepted so old and in-flight sessions stay comparable.

- remote frontier

Closed API models live in the remote-frontier lane because pretending their hidden parameter counts are known would be benchmark fan-fiction.

* SWE-bench

SWE-bench is an optional second benchmark layer. The lab generates three prediction files per instance and delegates pass/fail to the official Docker evaluation harness.

The three generation conditions are:

- =base=: issue plus deterministic lexical repository context, one patch attempt;
- =agent_plain=: same initial context plus read/search/apply-diff tools;
- =rlm_agent=: identical agent tools plus persistent SWI-Prolog symbolic memory/query.

Install the isolated SWE-bench dependencies and verify Docker/harness prerequisites:

#+begin_src sh :async yes
make swebench-deps
make swebench-doctor
#+end_src

Validate the official evaluator against a gold patch before model experiments:

#+begin_src sh :async yes
make swebench-gold | ./scripts/filter-output --lines 120
#+end_src

Generate a small three-condition SWE-bench Lite batch with the local model:

#+begin_src sh :async yes
make swebench-generate SWE_LIMIT=3 SWE_TURNS=8 MODEL_ID=qwen3-8b-q4-k-m | ./scripts/filter-output --lines 180
#+end_src

The generator prints a session id. Evaluate all three prediction files with the official harness:

#+begin_src sh :async yes
make swebench-evaluate SWE_SESSION=<session-id> SWE_WORKERS=2 | ./scripts/filter-output --lines 200
#+end_src

Generated predictions and telemetry live under =results/swebench/= and are gitignored. Repository mirrors are cached under =.cache/swebench/=.

* Reproducibility notes

- Keep raw rows. Do not overwrite them to make a chart prettier.
- Pin model IDs when a provider supports immutable snapshots.
- Record provider, endpoint class, quantization, context, and decoding settings.
- Keep the benchmark id distinct from the provider model name, but make both truthful.
- Treat API aliases as mutable unless the provider explicitly documents them as pinned.
- Compare recursion curves under the same token and call budgets.
- Compare =base=, =agent_plain=, and Prolog-RLM with the same model and initial context before attributing gains to symbolic reasoning.
- SWE-bench pass/fail comes from the official harness, not an LLM self-grader.
- Report failures, timeouts, malformed responses, and missing usage metadata rather than silently dropping them.
