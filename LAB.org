* Benchmark matrix

The current experiment matrix is defined in [[file:config/experiment.toml][config/experiment.toml]].
The current model registry is [[file:config/models.toml][config/models.toml]].

The intended size lanes are:

- sub-1B
- 1-3B
- 3-6B
- 7-12B
- 20-30B dense
- efficient MoE
- large MoE
- frontier open-weight
- remote frontier

Closed API models live in the remote-frontier lane because pretending their hidden parameter counts are known would be benchmark fan-fiction.

For a normal single-model llama.cpp server, run one model id at a time and accumulate sessions in =results/raw=. The examples below use =qwen35-4b=; change =MODEL_ID= for the model currently loaded by llama.cpp.

* Generate FINDINGS.org with gptel

The template is generated by Elisp, then the benchmark summaries are fed to your currently selected gptel backend/model. =gptel-request= is asynchronous, so Emacs remains usable while the findings are generated.

** 1. Reset findings template

#+begin_src emacs-lisp :results output
(rlm-lab-write-findings-template)
(princ "FINDINGS.org template written\n")
#+end_src

** 2. Preview the evidence packet

#+begin_src emacs-lisp :results output
(princ (rlm-lab-findings-context-preview 5000))
#+end_src

** 3. Generate findings asynchronously

#+begin_src emacs-lisp :results output
(rlm-lab-generate-findings)
(princ "gptel request dispatched; FINDINGS.org will be replaced on successful completion\n")
#+end_src

* Reproducibility notes

- Keep raw rows. Do not overwrite them to make a chart prettier.
- Pin model IDs when a provider supports immutable snapshots.
- Record provider, endpoint class, quantization, context, and decoding settings.
- Treat API aliases as mutable unless the provider explicitly documents them as pinned.
- Compare recursion curves under the same token and call budgets.
- Report failures, timeouts, malformed responses, and missing usage metadata rather than silently dropping them.
